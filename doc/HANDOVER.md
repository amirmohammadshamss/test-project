# راهنمای تحویل نارنج

## چه چیزی آماده شده است؟

نارنج برای مدیریت میزها، ثبت سفارش و هماهنگی سالن با آشپزخانه ساخته شده است. محیط فعلی محلی و نمایشی است؛ راه‌اندازی عمومی، بررسی عملی روی مرورگر و اتصال واقعی هوش مصنوعی هنوز تأیید نشده‌اند. پرداخت و حسابداری در این نسخه وجود ندارد.

## شروع کار کارکنان

1. نشانی برنامه را باز کنید و با حساب کاری وارد شوید. حساب‌های نمایشی و رمز فعلی در README هستند.
2. پرسنل سالن: میز آزاد را انتخاب کنید و اقلام را اضافه کنید. تعداد تا پیش از شروع آماده‌سازی قابل تغییر است.
3. آشپزخانه: سفارش را به «در حال آماده‌سازی» و سپس «آماده سرو» ببرید.
4. پرسنل سالن: پس از تحویل غذا، «تحویل به مهمان» را ثبت کنید. وقتی تمام اقلام سرو شدند، سفارش را ببندید تا میز آزاد شود.
5. مدیر: غذاها، قیمت و موجودی را در منو ویرایش کنید. دستیار منو تنها پیش‌نویس می‌سازد؛ قیمت و جزئیات باید توسط شما بررسی و تأیید شوند.

اگر پیام خطای ارتباط دیدید، موفقیت را فرض نکنید. برای تکرار همان درخواست از همان دکمه استفاده کنید. اگر همکار شما سفارش را تغییر داده باشد، اطلاعات تازه دریافت می‌شود و باید تغییر خود را دوباره بررسی کنید.

## محدودیت‌های مهم

- اینترنت و اتصال به سرور لازم است؛ کار آفلاین کامل نداریم.
- تغییرات همکاران تقریباً هر پنج ثانیه نمایش داده می‌شوند.
- سفارش خالی قابل بستن نیست. لغو سفارش/قلم در نسخه فعلی وجود ندارد؛ قبل از استفاده واقعی باید مسیر لغو اضافه شود.
- تعداد غذای در حال پخت قابل تغییر نیست؛ درباره اشتباهات با مدیر هماهنگ کنید.
- تکمیل سفارش به معنی ثبت پرداخت نیست.
- حساب کارکنان و دسترسی شعبه توسط مسئول فنی تنظیم می‌شود؛ دعوت و مدیریت تعاملی کارکنان نداریم.
- در هر نشست یک شعبه فعال است. قیمت‌های نمونه ساختگی هستند.
- نبود سرویس هوش مصنوعی مانع ثبت سفارش و کار آشپزخانه نمی‌شود؛ غذا را می‌توانید دستی وارد کنید.

## پنج قابلیت بعدی به ترتیب اولویت

1. لغو کنترل‌شده سفارش/قلم با دلیل، دسترسی مدیر و ثبت سابقه.
2. مدیریت حساب و دسترسی کارکنان و انتخاب شعبه مجاز.
3. ثبت پرداخت و تسویه با بازبینی نیازهای مالی واقعی.
4. چاپ رسید/نمایشگر اختصاصی آشپزخانه و پایش عملیاتی.
5. گزارش فروش و موجودی پس از اعتبارسنجی جریان اصلی با کارکنان.

## رشد تعداد رستوران‌ها

- **۱۰ رستوران:** یک سرور ممکن است کافی باشد، ولی این ادعا با آزمون بار اثبات نشده است. پایش، بکاپ، نرخ‌محدودسازی مناسب کاربران و بررسی تجربه کارکنان اولویت دارند.
- **۱٬۰۰۰ رستوران:** تازه‌سازی مکرر صفحه‌ها، اتصال‌های پایگاه داده و صف مشترک احتمالاً فشار ایجاد می‌کنند. نیاز به آزمون بار، صفحه‌بندی، تجمیع درخواست‌ها، اتصال‌های مدیریت‌شده و کنترل مصرف هر رستوران داریم.
- **۱۰۰٬۰۰۰ رستوران:** معماری فعلی به‌صورت ارائه‌شده مناسب این مقیاس نیست. تفکیک ظرفیت داده/صف، کنترل بار، تیم عملیات، بازیابی بحران و طراحی چندناحیه‌ای باید بر اساس اندازه‌گیری انجام شود. وعده ظرفیت بدون آزمون داده نشده است.

برای راه‌اندازی و نگهداری، مسئول فنی باید راهنمای DEPLOYMENT.md را دنبال و نتیجه بررسی‌ها را ثبت کند.

## Admin expansion

See [ADMIN_IMPLEMENTATION.md](./ADMIN_IMPLEMENTATION.md) for migration, controlled platform seed and startup instructions. Manager routes start at `/dashboard` on port 3000; Super Admin starts at `/login` on port 3001. The platform demo seed is opt-in and rejects production mode. Explicit restaurant JWT audiences require existing users to log in again. Production MFA/onboarding, browser verification and external deployment gates remain open.
